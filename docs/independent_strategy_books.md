# 独立策略账本与迁移边界

本实现用于三仓拆分后的交易宿主。一个真实 CTP 账户只由一个交易进程写入，账户内允许同一合约多个实例分别做多或做空，不内部撮合、不净额改写策略仓位。未配置 `strategy_initial_capital` 的历史运行沿用原账本路径。

## 权威归属与事务

策略实例 ID 是订单、成交、经济持仓、资本和 pending exit 的持久 owner。`component_id` 单独标记算法内部组件；不能把组件 ID 当成另一个实例或账户。账户 ID、实例 ID 和状态 namespace 在上线后不得通过改名获得“新”持仓。

`position_summary/position_detail` 保留每个实例自己的经济 FIFO 成本。`broker_position_summary` 是账户按合约、投保标记、方向和今昨划分的物理账本。实例 B 平自己的经济今仓时，经已验证的柜台规则可以消耗账户物理昨仓；B 的已实现盈亏来自 B 自己的成本，实际平今/平昨手续费来自物理分配。其他实例的经济成本不变。两个方向分别记账。

每笔成交继续使用既有 canonical TradeIdentity、WAL receipt、领域事务和 outbox。经济 lots、物理今昨、实例资本、预留消耗和 outbox 同一事务提交；重复成交不再计费。未知 owner 或估值规则不完整的成交保持未完成/冲突，不猜测归属；账户对账不一致阻止开仓。

## 资本与并发占用

实例权益 = 初始分配 + 显式划拨净额 + 自身累计已实现盈亏 − 自身累计费用 + 自身按开仓成本计算的浮盈亏。

开仓前的领域账户锁同时读取权益、经济持仓和 `strategy_open_reservations`。占用使用多空各自的保守毛保证金，加上尚未记账的委托预留保证金和手续费；通过后持久预留。成交在相同事务将预留转入经济持仓和实际费用。撤单或成交状态中已报告、尚未记账的成交继续占用，避免迟到成交期间重复使用资金。CTP 账户可用资金和物理平仓冻结仍是另外的账户硬约束。

`strategy_close_reservations` 同时限制自身可平数量，CTP 物理 ledger 限制账户今昨可平数量。账户内潜在自成交拒绝较新订单，不能自动撤销其他实例订单。部署的单笔数量、名义金额限制对所有订单生效；开仓时间窗和资金比例限制只阻止开仓。

策略资金划拨通过 `TransferStrategyCapital` 显式提供唯一 transfer_id、来源、去向、金额和原因。仅在相关两个实例自然无仓、无活动订单、无未记账预留时执行；事务同时写双边调整和 journal。同一 ID 的相同重试幂等，不同内容拒绝。首版提供领域接口，未提供远程资金划拨服务。

账户总保证金比例还按所有实例经济多空的毛保证金及全部未记账开仓预留校验，不能用多空净额或柜台组合优惠绕过配置的账户总上限。策略预留事务同时校验这一总额；实际柜台可用资金仍另外限制下单。非投机开仓因尚无按套保标记隔离的完整费率查询视图而明确拒绝；已有成交、经济账、物理账与退出保留其真实套保标记。

订单状态回报只推进累计成交水位和暂估冻结，不直接确认实际费用。账户资金投影在领域成交事务成功后确认对应成交身份和数量。账户查询开始时记录本地提交/处理代次和 WAL receipt；完成后只有这两个水位均未改变、可靠回报队列已排空、没有活动委托或未记账成交时才可替换本地保守冻结。普通刷新保留本地冻结覆盖层，重连或查询交错不会提前释放资金。撤单请求被拒绝属于撤单动作失败，原委托仍保持冻结。

## 对账差异桥

账户 CTP 报表可能采用当日结算成本和当日累计值，策略采用自资本原点以来的开仓成本。因此每个完整账户快照记录 `strategy_capital_reconciliations`：已实现口径差、浮动口径差、费用口径差，以及现金/结算/未分配资本桥。恒等式：

账户权益 − 策略权益合计 = 现金与结算桥 + 已实现口径差 + 浮动口径差 − 费用口径差。

桥列只是可审计差额，不是已核准资金来源，不自动分摊到策略。缺行情或估值输入时无法生成完整桥，开仓资金校验也保持拒绝。账户 Redis 持仓今昨投影来自物理账；策略恢复继续读取经济账。

## 带仓迁移步骤

1. 在隔离副本演练，冻结原配置、release、参数哈希、ID、state namespace、SQL 和 WAL 水位并备份。SQL 变更在停止写入后执行 `infra/timescale/init/009_independent_strategy_books.sql`；不能把本说明当成已执行生产迁移的证据。
2. 核对已有每笔成交与持仓 owner、交易日和完整估值。配置初始资本的原点必须与被导入的历史盈亏范围一致，不能把当前权益再次当成历史初始资本。未知 owner、不完整历史、跨日不齐必须先形成明确迁移记录，宿主不会自动填补。
3. 初次配置总分配必须不高于已确认的正数账户权益；恢复已有资本账时校验原初始分配完全一致，正常历史亏损不会导致重新分配。改变分配走显式 journal。
4. 启用时保留已有经济 lots 并以其今昨合计创建物理起点，随后用完整柜台订单/成交/持仓查询核对。已有未结束平仓订单会恢复自身预留；旧开仓订单若没有持久资金预留保持 HOLD，等待明确恢复处理，不能猜测过去的冻结。无需强制平仓来迁移已有持仓。
5. 新实例模式的策略状态必须含账户、instance ID、release、parameter hash 和 state schema 的封壳。与现有状态不兼容时拒绝恢复，不能静默清空；旧无封壳的状态需受控转换和等价验证。旧未启用实例模式的状态格式保持兼容。
6. pending exit 仅在本实例持仓为零、本实例平仓冻结为零、账户成交投影完成对账后删除；其他实例同合约持仓无需为零。

pending exit 新写入采用 v3，持久保存 `component_id` 与 `hedge_flag`，按实例、合约、方向及套保标记区分退出。旧 v2 记录按其历史投机语义恢复，不推断组件身份。恢复发现未写完的最后一条记录时，先截断并 fsync 到最后一个完整换行，再允许新追加；完整行损坏仍拒绝恢复。

## 验收范围

离线测试覆盖：同账户同合约独立多空、经济/物理今昨差异与实际费率、重复和迟到成交、并发开仓/平仓预留、事务故障回滚、资本 journal 幂等/守恒/拒绝划拨持仓资本、差异桥恒等式、实例独立状态和退出、Redis 物理投影。迁移 SQL 尚未在现有运行数据库执行，也未连接 SimNow 或发送实盘订单。真实重连、柜台成交顺序及连续运行仍需后续受控验收。

独立复核后，`docs/results/p4_online_review_ctest.log` 记录 119 个定向用例全部通过，包含网关及 trader adapter 查询边界透传、总毛保证金与多实例冻结、撤单拒绝保留预留、错误成交范围事务回滚、pending exit 旧格式及损坏尾部恢复。该证据来自模拟适配器和内存事务后端，不代表外部 Timescale 迁移或真实 SimNow 五日验收。

后续另完成真实 CTP SDK 编译，以及独立 PostgreSQL 14.24 临时数据库的 8/8 libpq 集成测试（含 009 迁移、经济/物理分配、跨实例总预算并发）。详细范围、二进制及包哈希见 [真实 SDK 与隔离 SQL 验证](results/online_real_and_postgres_validation.md)。临时数据库已停止，未连接交易前置、现有数据库或运行账户。
