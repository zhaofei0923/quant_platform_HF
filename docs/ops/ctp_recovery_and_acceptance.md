# CTP 候选版本：恢复、迁移与验收

本轮交付用于研究回归和 SimNow 验收。构建与单测结果见
[基线及 SDK 记录](../results/ctp_remediation_20260906/baseline.md)，研究参数迁移见
[回测运行语义](../backtest_runtime_semantics.md)。真实资金部署需要另行接入测试与切换批准。

## 运行身份和存储

在线恢复目录固定为 `runtime/<environment>/<broker>/<account>/<instance>/`。
`QUANT_HFT_RUNTIME_ROOT` 可指定根目录，`QUANT_HFT_INSTANCE` 默认 `default`。
`run_id` 仅标识本次运行。环境只允许 `sim`、`simnow`、`prod`。
目录保存身份清单；同一根目录中，一个账户只允许一个运行实例持有锁，避免不同实例
绕过进程内的串行准入。这不是跨主机分布式主备锁；同账户不能通过不同根目录或主机
启动多个活动实例。

显式 WAL、状态或缓存路径必须匹配身份；已有非空且未绑定的旧路径会被拒绝。
`QUANT_HFT_WAL_FILE` 是通用覆盖项；兼容的 `SIMNOW_WAL_FILE` 只允许用于 SimNow，
二者同时设置时必须一致。Redis 投影和策略 checkpoint 的键同样按身份隔离。
外部领域账本失联时禁止开仓，不自动切换为空内存账本。

WAL 收据、领域提交、投影消费分别维护水位。关键回报在异步分发前同步写入 WAL；
已满的内存队列只作为加速队列，持久化积压顺序补送。订单映射准备记录可靠提交后
才允许发送；发送结果不明时保留预留并查询，不直接释放或重新报单。

## 启动及恢复顺序

1. 取得身份锁，验证 WAL 完整性，再重放订单映射、未完成交易和委托生命周期。
2. 恢复领域持仓及独立消费的持仓、风险、策略投影；策略消费在回调和快照保存后确认。
3. 补齐柜台委托和成交，完成当前连接代次的全账户持仓查询。
4. 按账户、合约、交易所、方向、套保及日期桶对账；不以净持仓掩盖多空差异，也不把
   账户总仓位覆盖到每个策略。对不明归属和未确认基线保持阻断。
5. 完成行情与策略预热后才恢复开仓。行情缺口不得用最新价格替换缺失 Tick；需要
   完整 Bar 恢复流程。已有仓位的风险状态不能因指标重新预热而清空。

撤单提交成功不是撤单终态。订单终态先到不抑制后到真实成交；重复成交按领域身份
去重，载荷冲突进入对账。通用 Close 的日期分配和费用估值只使用已确认的规则输入。
真实 API 的新成交缺少核算证据时，原始回报可靠保存在 WAL，领域入账保持待处理，
交易权限继续阻断；已提交成交的重复回报仍可修复投影，不要求重新核算历史事实。

## 本地账户配置与核算证据

项目根目录已创建本地 `.env`，凭据字段留空，由账户使用者填写。该文件受 Git 忽略，
无需把内容发到聊天或日志。Linux 6.7.11 SDK 已复制并完成编译链接检查；在交易时段
测试前，还需核对本地填写的前置、账户和有效合约。当前没有进行 SimNow 登录。

`core_engine` 通过 `QUANT_HFT_ACCOUNTING_POLICY_FILE` 读取本地核算规则 JSON；
填写文件绝对路径后重启载入。[规则说明及示例](verified_accounting_policy.md)列出完整字段。
规则限定环境、经纪商、账户、交易日、合约、交易所和套保标志，并保存规则来源、
版本及样本哈希。规则文件本身不能开放交易：每次连接还必须成功完成当日合约信息、
成交手续费和报撤单手续费三类查询，结果与规则精确匹配，且查询证据同步落盘后，
才可解除 `trade_semantics_unverified`。预热、对账和其他权限条件仍独立生效。

当前只支持显式验证的 `money_plus_volume_v1` 费用模型、`close_allocation_v1`
费用日期分配和零报撤单费；柜台返回非零报撤单费时保持阻断。通用 Close 优先级
必须有验证来源。不要把测试里的数值和样本哈希复制成账户的实际规则。

已保存的匹配证据仅可用于恢复启动前的历史 WAL，不能代替新会话查询。若旧日 WAL
存在未提交成交且从未保存匹配证据，不能用今日费率补记；需先补齐可核验的历史
证据迁移方案。首版未提供任意历史证据导入工具。

## 旧状态迁移

不要直接把旧文件拷入活动恢复目录后补一份身份清单。旧 WAL 缺少可靠接收序号、
交易日、经纪商或策略归属时，无法仅凭文件名证明身份和成交覆盖边界。

提供离线复制审核工具，必须在原运行进程停止后执行：

```bash
bash scripts/ops/stage_runtime_migration.sh \
  --source /absolute/path/to/stopped-runtime \
  --staging-parent /absolute/path/to/migration-review \
  --environment simnow --broker TEST_BROKER --account TEST_ACCOUNT --instance default
```

该工具保留原件，拒绝符号链接、活动锁和源目录内的目标目录，比较复制前后与副本的
SHA-256 清单。已有身份清单必须完全匹配；无清单的旧状态复制后返回 3，标记为
`unverified_legacy`。工具不转换 WAL、不生成活动身份，也不自动推广副本。

推广前仍须核验 WAL 格式及全部成交身份、策略归属、账本提交水位、基线覆盖集合和
柜台快照。无法确认时继续阻断，保留审核副本和原件。当前没有可以对任意旧状态安全
执行的一键转换器；旧格式只读能力不代表允许自动接管有仓账户。新版本创建的状态
不得交给旧二进制直接读取。

## SimNow 五日验收表

验收开始前确认目标 SDK、账户权限、选定前置、交易日历、合约与费用语义；凭据只留
本地 `.env`。至少连续五个完整交易日，覆盖两个夜盘和一次交易日切换。每天保存：

| 记录 | 必填内容 |
|---|---|
| 运行身份 | 构建提交、环境、脱敏账户标识、实例、运行 ID、开始/结束时间 |
| 市场输入 | 数据范围、夜盘及交易日、缺口/恢复记录、完整 Bar 预热起止 |
| 关键回报 | WAL 首末接收序号、校验结果、领域提交水位、各投影消费水位 |
| 交易核对 | 委托终态、原始成交身份、已应用/重复/冲突数量、日期桶及策略归属差异 |
| 故障演练 | 断线、进程重启、部分成交撤单、发送不明、存储失败的触发与恢复证据 |
| 性能 | 固定输入规模、吞吐、P99、队列最高水位、计时迟到、WAL 延迟、峰值内存、恢复耗时 |

验收只有在柜台持仓、领域账本和策略归属可逐项核对，关键事件无静默丢失，所有故障
都有确定结果后通过。现有短样本、模板化编排演练及脚本成功状态不替代真实恢复证据。

## 明确保留的边界

- 本地 WAL 验证重放目前有 256 MiB 文件上限；超限拒绝恢复，尚未完成分段连续恢复。
- 外部事务已在隔离 PostgreSQL 验证；这不等于既有 Timescale 生产部署和 Redis 服务
  故障矩阵已全部验收。
- 通用平仓优先级、完整费用/保证金估值和有仓账户首次接管需要目标柜台样本。
- Arrow 输入读取已改为批次游标；完整成交、轨迹、结果及编码页仍另占内存。
- TSan 能否运行取决于目标宿主支持；编译成功与运行通过必须分别报告。

上述限制不能通过清空 WAL、覆盖账户持仓或放宽 Ready 门控绕过。
