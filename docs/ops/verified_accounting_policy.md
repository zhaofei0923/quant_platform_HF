# 已核验交易入账政策

真实 CTP 模式默认带 `trade_semantics_unverified` 阻断原因。设置 `QUANT_HFT_ACCOUNTING_POLICY_FILE` 为私有本地 JSON 的绝对路径，并重启，使政策载入；没有简易跳过开关。示例为 [accounting_policy.example.json](../../configs/accounting_policy.example.json)，其中 `verified=false`、零值和 `REPLACE_...` 都是占位符，不能作为已核验柜台事实使用。不要把真实账户资料或原始柜台样本提交到仓库。

人工核对经纪商样本后填写每项事实及其来源、版本和样本 SHA-256，再将对应记录标为已核验。程序只验证记录格式与查询数值一致性，不能替代人工确认平仓优先级或费用日期归属。环境、经纪商、账户、完整合约、交易所、套保类型和交易日均精确匹配，没有产品通配范围或跨日默认政策。套保类型 `0/1/2` 分别是投机、套利、套保。SHFE/INE 的优先级必须填写 `exchange_explicit`；其它交易所必须依据已核验规则填写 `today_first` 或 `yesterday_first`。不能据旧教程为所有非 SHFE 合约设置统一默认值。

每次连接会话都要取得当日完整的合约、手续费、报撤单费用三个查询结果。乘数、账户、交易所、费用数值、来源和查询范围逐项匹配；不完整或失败的新查询会撤销当前证据。同日重连也不复用上一会话的查询缓存。手续费查询返回产品 ID 时，`commission_instrument_id` 应写该原始行 ID，且该查询必须明确针对记录中的完整合约；全量查询不能据此推断产品映射。

支持的费用模型仅为 `money_plus_volume_v1`：价格 × 合约乘数 × 手数 × 按金额费率，加手数 × 按手费率。只有样本证实费用的今昨分配与实际持仓平仓分配相同，才可声明 `fee_date_basis=close_allocation_v1`。ApplyTrade 先确定 CloseAllocation，再在同一事务计算平今、平昨费用并记录来源版本。下单前泛平仓资金预留取两桶费率的保守上界；它不是已成交费用。非零报单或撤单费用尚无独立费用事实账，因此本入口不支持并保持阻断。盈亏使用明确的 `opening_lot_v1` 开仓逐笔成本，不宣称等同柜台逐日盯市或结算价盈亏。

当前全部活动合约匹配后，主入口先把查询匹配证据写入身份绑定运行目录的 `state/accounting_policy_evidence`，完成文件与目录同步，再清除这一项阻断原因；其它恢复、风控和行情条件仍需满足。每个执行切片再次核对实际合约和套保范围。未验证的新真实成交只可靠接收到 WAL，不提交领域入账事实或推进该收据水位。已入账的重复成交按原始载荷去重，可用原始 outbox 与 CloseAllocation 修复投影，不因当前政策缺失而重复入账或无法重投。

重启时保存的证据只可用于经过完整 WAL 校验的启动前收据范围，并且政策内容必须完全相同；当前放行仍需新会话查询。若历史未提交成交从未拥有对应的持久查询证据，或政策已移除/变更，历史恢复保持失败，不能用今日费率补造旧日事实。本轮没有提供历史证据导入工具，也不会自动重新估值已提交的旧账。

外部数据库升级需停写并在 007 后执行 [008_verified_trade_fees.sql](../../infra/timescale/init/008_verified_trade_fees.sql)。模拟适配器仍可使用原显式费用接口，不因真实接口的政策门禁改变离线演练默认行为。此入口及离线测试不构成真实柜台自动交易验收；实际交易时段验证流程见 [恢复与验收](ctp_recovery_and_acceptance.md)。
